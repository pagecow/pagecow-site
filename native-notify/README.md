# Agent Notify — push setup for pagecow-site

_Generated by Agent Notify (recipe v1, stack: Other — any framework (REST) — best guess: Next.js)._

This pull request adds the Native Notify device-registration client for your
stack. Push delivery (APNs for iOS, FCM for Android) is handled by Native
Notify — no Expo dependency, no extra push infrastructure.

> **Do not commit real credentials.** `NN_APP_ID` and `NN_APP_TOKEN` are read from the app's own configuration at build/run time.

## Steps to finish (the agent cannot do these for you)

1. **Get your app id + app token** from the Native Notify dashboard
   (your app → Settings). Put them in your app's configuration:
   - Keep NN_APP_ID / NN_APP_TOKEN in your server/app configuration, out of git.
2. **Get the device token** and call the registration function:
   - POST https://app.nativenotify.com/api/universal/device/register with { appId, appToken, deviceId, platform, tokens: { apnsToken?, fcmToken? } }.
   - Any language works — the endpoint is plain JSON over HTTPS.
3. **Run the app on a real device**, let it register, then click
   **Send a test push** in Agent Notify (or POST /api/universal/test-send).
   The result is immediate — accepted or failed with a plain-English reason.
4. **iOS only:** make sure Push Notifications capability is enabled and the
   App ID has the Push Notifications feature.

## Verify

The agent's verification loop sends a real test push through the production
pipeline and reports the exact result. If it fails, the failure code maps to
a fix:

| Result | What it means |
| --- | --- |
| accepted | The device token is valid and credentials work end-to-end. |
| BadDeviceToken | Token is wrong / from the other APNs environment (debug vs release). |
| Unregistered | The app was uninstalled or the token was revoked — register again. |
| InvalidProviderToken | The APNs .p8 / key id / team id in Native Notify settings are wrong. |
| SENDER_ID_MISMATCH | The FCM service account does not match the app's Firebase project. |
